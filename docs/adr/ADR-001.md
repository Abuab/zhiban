## 一、背景

「知伴」需在 4C4G 单机、一人可运营的约束下交付：小程序（uni-app + Vue3）+ 服务端（NestJS）+ 管理后台（Vue3），且必须满足宪章 P5——「题目、维度、计分、报告文案、价格、锦囊、页面文案、开关全部后台可配，任何硬编码进代码的题/文案 = 工程事故」。

本 ADR 记录以下决策：① 整体技术栈；② 规则引擎方案；③ 模板引擎方案；④ 配置化落库形态；⑤ P1 免费模式下的专属卡成本闸门。

---

## 二、决策 1：整体技术栈

### 选项
| 选项 | 说明 |
|---|---|
| A. uni-app + Vue3 + NestJS + MySQL 8 + Redis | 规格既定方案 |
| B. 微信原生小程序 + NestJS | 少一层框架，但无法复用到 H5/其他端 |
| C. Taro + NestJS | 与 A 等价，生态略小 |

### 决定
**采用 A**，与规格《基础设施与部署方案 v0.1》完全一致。

### 理由
- 规格已固化选型，且 uni-app 可复用 Vue3 技术栈，管理后台（Vue3 + Element Plus）与小程序端可共享类型定义与工具函数，降低「一人可运营」的维护成本（P6）。
- NestJS 的模块化（Module/Guard/Interceptor/Pipe）天然承载「鉴权中间件、统一响应、全局异常、rate limit」四项脚手架要求。

### 后果
- 需自行维护 uni-app 编译链与多端兼容，但本版本只出微信小程序端，风险可控。
- 队列不引入独立 MQ（见 §五）。

## 三、决策 2：规则引擎方案（核心决策）

### 选项
| 选项 | 优点 | 缺点 |
|---|---|---|
| A. 引入商业/开源规则引擎（Drools、json-rules-engine） | 规则与代码分离彻底，声明式 | 依赖重、学习与调试成本高；本项目规则仅 8 条且已固定，属过度设计 |
| B. 全硬编码 if-else | 简单 | 直接违反宪章 P5，G1 验收失败 |
| C. **DB 驱动配置 + 纯函数计算服务（自研）** | 规则参数（阈值、聚合方式、评级命名）全落 `scoring_rule` 表；计算逻辑为无副作用纯函数 | 新增「规则种类」仍需发版（但规格明确规则种类不变） |

### 决定
**采用 C。** 具体形态：

1. `scoring_rule` 表承载**参数化配置**：聚合方式、差值阈值（15/30）、评级命名、低质量时长阈值。
2. 计分引擎（`ScoreEngine`）为**纯函数服务**，入参 `(scaleVersionSnapshot, answers)`，出参 `(dimensionScores, flaggedItems, baselineTriggered, qualityFlag)`；不依赖 DB / HTTP，保证 8 条规则可 100% 单测覆盖（模块 3 完成标准）。
3. 8 条规则全部落在同一引擎，逐条对应题库 v1.0 第三部分：
   - 规则 1 反向题翻转（`6 - 原值`）
   - 规则 2 维度分 `(均分 - 1) × 25` → 0-100（**阶段 0 裁决 D-2，修订原「×25」**）
   - 规则 3 选择题不参与维度分，仅作分歧比对
   - 规则 4 逐题分歧（量表 |差| ≥3 / 选择项不同），每维度取分差前 2
   - 规则 5 差值分级，**恰好等于阈值归入较低一级**（D6）
   - 规则 6 底线组任一题 1-2 分 → 触发中性核实提示（R5/B9）
   - 规则 7 作答质量（时长 <3 分钟 或 全部同值 → low）
   - 规则 8 16 型：每维度 6 题，A 端数 ≥4 → A，≤2 → B，=3 → 按「**平局取 B 端**」（阶段 1 假设 A-7，待确认）

### 后果
- 运营改阈值/命名 → 改表即可，零发版。
- 新增「一种全新计分算法」仍需发版，但规格承诺规则种类冻结，可接受。

## 四、决策 3：模板引擎方案

### 选项
| 选项 | 优点 | 缺点 |
|---|---|---|
| A. Handlebars / EJS 全功能模板 | 能力强 | 支持任意 JS 表达式，配置者可写逻辑 → **模板注入 + 配置事故风险**；与 P5「文案可配」边界过宽 |
| B. **白名单占位符渲染（自研）** | 仅支持 `{维度名} {分数} {昵称A} {差值}` 等白名单变量，无表达式求值 | 表达力弱，但报告文案不需要逻辑 |
| C. 前端模板（小程序端拼装） | 无服务端渲染成本 | 文案硬编码在前端，违反 P5 |

### 决定
**采用 B。** 后缀式极简渲染器：

- 占位符白名单由 `report_template_block.template_text` 中出现的键决定，渲染时从受控上下文取值；未知占位符 → 渲染为空并记审计日志，**不抛错、不执行**。
- 模板文本存于 `report_template_block`（按人群 × 可见层级 L1/L2/L3 多维），历史报告通过 `report.template_version_id` 指向旧版本渲染（D5/B8）。
- 内容详实度下限（价值感标准 §一：维度解读 300-500 字、对话建议 ≥3 条）以 `min_chars` 做**运营侧校验**，不参与渲染。

### 后果
- 彻底规避模板注入，同时满足「改文案零发版」。
- 若未来报告需要条件分支（如按评级显示不同段落），通过**多模板行 + block_key 筛选**实现，而非模板内 if。

## 五、决策 4：配置化落库形态与缓存

1. **量 tables 采用「版本化 + 冻结不可变」模式**：`scale` → `scale_version`（draft → frozen）→ `scale_dimension` / `scale_question`。冻结后的版本**永不编辑**，运营修改 = 复制生成新 version（落实 B8 / G1）。
2. `invite.scale_version_id` 在邀请创建时锁定；`answer_snapshot` 冗余存 `scale_version_id`，保证历史报告永远用旧版渲染。
3. 配置读取走 **Redis 缓存**：量表/计分/开关缓存 60s + 变更主动失效；运营位/内容域直接查库（低频）。
4. **异步与队列**：Redis + BullMQ（`report_generate` / `share_image` / `invite_expire`），不引入独立 MQ——4C4G 单机下独立 MQ 属运维过度设计（P6）。
5. **对象存储**：长图、插画、分享卡片一律 COS + CDN（规格 §1）。

## 六、决策 5：P1 免费模式下的 AI 专属卡成本闸门

### 背景
规范增补 v0.3 §二 的成本控制原为「专属卡仅在付费解锁后触发」。阶段 0 裁决 D-1 取消付费后该闸门失效，大模型调用将直接暴露给全量用户。

### 决定（需产品负责人确认，见阶段 1 假设）
以**次数与缓存**替代付费闸门：

1. **生成粒度**：`exclusive_card` 表对 `(invite_id, topic_id)` 建唯一键 → 同一邀请同一议题**全局只生成 1 次**，双方共用同一结果。
2. **触发前置**：必须（a）已登录 且 （b）该邀请已达 `report_unlocked` 状态（即双方答题齐备，数据源才完整）。
3. **限流**：单用户每日专属卡生成触发上限 N 次（`feature_flag` 可配，默认 5），防刷接口。
4. **降级链**：生成 → P7 禁词校验 → 失败重试 1 次 → 仍失败则 `status=degraded`，返回通用卡并记审计（增补 v0.3 §二）。
5. **审计**：每次生成写 `audit_log`（viewer、时间、prompt 版本、model、token 用量），便于成本核算。

### 后果
- 成本从「客单价覆盖」转为「获客成本」科目，需在预算内设置日调用上限；超限时降级为通用卡。
- 若 P2 恢复付费，本决策可平滑回滚为「付费后触发」，表结构无需变更。

---

## 七、决策 6：支付模块本版本「空实现」而非「不实现」

- 保留 `PAY` 模块与 `GET /entitlements` 接口，固定返回「全部免费权益」。
- 前端所有「已解锁」判定统一走服务端接口（PRD-005 §1 要求），P2 上线支付时**前端无需重写**。
- 表 `order` / `entitlement` / `coupon` / `payment_notify_log` 建表保留、不写入。

---

## 八、总后果与风险

| 风险 | 缓解 |
|---|---|
| 自研规则/模板引擎的可维护性依赖文档 | 8 条规则逐条单测 + 模板占位符白名单显式登记 |
| 免费模式导致 AI 成本不可控 | §六 的次数 + 唯一键 + 限流 + 降级四重约束 |
| 4C4G 单机为单点 | 每日异地备份 + binlog（规格 §3）；降级维护页（G5） |
| 配置误改影响线上 | 冻结版本不可变 + 后台操作全量写 `audit_log` |
| 阶段 1 假设未经确认（A-1~A-7） | 阶段 1 人审门禁逐条确认后才进入阶段 2 |
