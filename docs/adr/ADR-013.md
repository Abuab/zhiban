## 一、背景

UI 与流程重构要求：进入敏感维度前保留 **B7 阻断式单独同意**；同意后，在该维度内**每道题**允许用户选择「不愿回答」。产品负责人已裁决采用**逐题**粒度（而非整维粒度）。

现状核实（均为实测）：

| # | 事实 | 出处 |
|---|---|---|
| 1 | 现有跳过是**维度级**：入参只有 `skippedDimensions`（只接受 `is_sensitive = 1` 的维度编码，非法即 `10001`） | `save-answers.dto.ts` L36-42、`assessment.mapper.ts` L157-178 |
| 2 | `answer_sheet` **无逐题跳过列**，只有 `skipped_dimensions_json` | `schema.sql` L157-178 |
| 3 | 当前**所有题目均必答**：交卷前 `assertComplete` 用 `findMissingQuestionCodes` 要求「除被跳过维度外全部有答案」 | `assessment.service.ts` L661-679、`assessment.mapper.ts` L219-230 |
| 4 | **计分引擎已天然支持单题缺失**：未作答的题「跳过、不计入均分分母」 | `scoring.engine.ts` L110-115 |
| 5 | 双人分歧引擎同样已支持：量表题 `scoreA === null \|\| scoreB === null → continue`；选择题同口径 | `diff.engine.ts` L153-155、L189-191 |
| 6 | ⚠️ **但引擎在「该维度一题都没答」时返回 `score = 0`**：`let score = 0; if (effectiveValues.length > 0) {…}` | `scoring.engine.ts` L117-124 |
| 7 | ⚠️ **服务层 `evaluated` 只认维度级跳过**：`evaluated = !skippedSet.has(code)`，不看有没有作答 | `assessment.service.ts` L745-757 |
| 8 | ⚠️ **双人比对的「未评估」集合只由维度级跳过推出**：`unevaluatedCodes = 双方 skippedDimensions 并集` | `double-report.engine.ts` L233-236 |
| 9 | ⚠️ **缺失分会退化为哨兵值**：`scoreMap.get(code) ?? MISSING_SCORE`，而 `MISSING_SCORE = 0` | `diff.engine.ts` L261-262、L42 |
| 10 | 补答范围以 `cache.skipped`（维度）为准，且补答后把 `skippedDimensionsJson` 置空 | `assessment.service.ts` L302-304、L323-329、L344 |

**事实 4/5 说明「逐题不做」在算法上是原生支持的；事实 6/7/8/9 说明它有三个必须堵住的口子** —— 否则会产出「被跳过 = 0 分 = 极端取向」的误读，以及**不存在的分歧**。

## 二、决策 1：新增 `skippedQuestionCodes`，与维度级 `skippedDimensions` 并存且**互斥**

### 入参
```
PUT  /api/v1/assessments/:id/draft      （§12.4）
POST /api/v1/assessments/:id/submit     （§12.5）
PUT  /api/v1/invites/:code/answers      （§13.6，复用同一 DTO）
POST /api/v1/invites/:code/answers      （§13.7，复用同一 DTO）
新增可选字段：skippedQuestionCodes?: string[]
```

### 白名单（fail-closed，对齐既有 `resolveSkippedDimensions` 的写法）
只接受**同时满足**两个条件的题号：
1. 题号存在于**该卷锁定的量表版本**（`scale_question.code`，VARCHAR(16)）；
2. 该题所属维度 `is_sensitive = 1`（当前唯一敏感维度为**维度 8 亲密与关系期待**，Q64-Q71）。

任一不满足 → `10001` 拒绝，**不做静默忽略**（与维度跳过同口径）。

### 由此天然排除
- **底线题 Q72-76**（`is_baseline = 1`，`dimension_id` 可为空）→ 不在敏感维度内，**不可跳过**。这一点很关键：否则用户可借「逐题跳过」规避 R5/B9 的底线题触发规则。
- **风格题 Q27** 与全部非敏感维度题 → 不可跳过。

### 互斥
同一维度**不得**同时出现在 `skippedDimensions` 与「`skippedQuestionCodes` 所覆盖的维度」中；出现交集 → `10001`。
语义上二者是两种不同的产品动作：整维拒绝授权（B7 弹窗选「不同意」）vs 已授权但个别题不愿答。

## 三、决策 2：落库形态 —— 新增 `answer_sheet.skipped_questions_json`

```sql
ALTER TABLE `answer_sheet`
  ADD COLUMN `skipped_questions_json` JSON DEFAULT NULL
    COMMENT '逐题拒绝作答的题号数组（仅敏感维度；ADR-013）；不参与维度分，报告不向对方暴露' AFTER `skipped_dimensions_json`;
```

- 与 `skipped_dimensions_json` **并列保留**，不合并：报告需要区分「整维未授权」与「已授权但个别题未答」两种文案。
- 答案净化：落入两个跳过集合的题号，**即使客户端传了答案也一律丢弃**（复用 `sanitizeAnswers` 的 `excludedCodes` 参数，`assessment.mapper.ts` L114-142）。
- 进度分母：两个集合的题号**都**不计入 `totalCount`（复用 `buildProgress`，`assessment.mapper.ts` L202-217）。

## 四、决策 3：**零有效作答的维度必须判为「未评估」**（堵住事实 6/7 的误读）

### 规则
> 一个计分维度若**没有任何一道题被有效作答**，则该维度 `evaluated = false`、`score = null`，**绝不写 0**。

### 实现（两层，缺一不可）
1. **引擎层**：`buildDimensionScore`（`scoring.engine.ts` L103-134）在 `effectiveValues.length === 0` 时返回 `score: null`（现状返回 `0`）。
   - `ScaleDimensionScore.score` 类型由 `number` 改为 `number | null`（`scale.types.ts` L114-122），并新增 `answeredCount`（**实际计入均分的题数**），与既有 `scoredCount`（题目定义数）并列。
   - 为什么放引擎而不是服务层：`0` 与「全选 1 分」的得分**数值相同**，只有引擎自己知道「这个 0 是算出来的还是没算」；把判别逻辑留在引擎，任何调用方都不会误用。
2. **服务层**：`evaluated = !skippedSet.has(code) && item.score !== null`（改 `assessment.service.ts` L748）。

### 理由
ADR-004 决策 2 已明确「未评估维度绝不写 0 分：全选 1 分恰好也得 0 分，写 0 会把『拒绝授权』误读为『极端取向』」。逐题跳过让「零作答」从**不可能**变成**可能**，该约束必须同步扩展到新路径。

### 部分跳过（不是零作答）的口径
维度内「答了一部分」时，维度分仍是**已作答题的均值**（`(均分 - 1) × 25`，分母自然缩小）。
- 计分公式不变；`scoredCount` 仍为题目定义数，`answeredCount` 反映实际作答题数。
- 该维度**仍参与**双人比对（见决策 4 的边界说明）。

## 五、决策 4：双人比对范围必须同步扩展（堵住事实 8/9 的**假分歧**）

### 现状缺陷
`double-report.engine.ts` L233-236 的 `unevaluatedCodes` 只由「双方 `skippedDimensions` 并集」推出。若某维度因**逐题跳过**导致一方零作答：
- 该维度**不在** `unevaluatedCodes` 里 → 进入 `comparableDimensions`；
- 该方 `dimensionScores` 已被 `evaluated && typeof score === 'number'` 过滤掉该维度（`double-report-generator.service.ts` L181-183）；
- `compareDouble` 取不到分 → `?? MISSING_SCORE`，而 `MISSING_SCORE = 0`（`diff.engine.ts` L42、L261-262）；
- 结果：**凭空算出一个「分差 = 另一方的分」的差异**，大概率落进「待沟通区」甚至「重点待沟通」。
  —— 用户会看到一段**双方根本没有分歧**的「待沟通」内容，直接违反 P7「不评判、不制造焦虑」与 R2 的「分歧」定义。

### 决定
`unevaluatedCodes` 的判定来源扩展为：
```
双方 skippedDimensions 并集
  ∪ { 任一方的 dimensionScores 中不含该维度 }     ← 新增
```
被排除的维度进入 `unevaluatedDimensions`，端上统一标注「未评估」，**不参与差值比对**（与 ADR-005 决策 7 的既有口径一致）。

### 边界说明
- **部分跳过不排除**：只要双方在该维度都有 ≥1 道有效作答，比对照常（维度分是均值，语义仍是「双方在该维度上的取向差异」）。
- **要不要告知用户「某维度只答了 x/y 题」**：报告在维度行展示聚合的 `answeredCount / scoredCount`（**不指明是谁少答**），属中性事实陈述，不违反 P7。
- **绝不向对方暴露「具体跳过了哪几题」**（见决策 6）。

## 六、决策 5：报告与隐私 —— 跳过明细**不向对方暴露**

| 视图 | 展示内容 |
|---|---|
| 本人（`GET /assessments/:id`、本人视角的 `SheetState`） | 可返回 `skippedQuestionCodes`（本人知道自己跳了哪些题） |
| 另一方（双人对比报告 L1 / L2） | **不返回任何题的跳过标记**；只给维度级聚合（`answeredCount / scoredCount`）与 `unevaluatedDimensions` |
| 逐题分歧清单 | 被跳过的题**天然不入清单**（事实 5：任一方未答即不记分歧） |

### 理由
「TA 跳过了 Q64（二人独处时间）」本身就是关于对方的高敏感推断。BD 只披露聚合，不披露题号。

> 注意：维度级 `skippedDimensions` **沿用既有口径**（双方可见「某维度未评估」），本决策不改变它。

## 七、决策 6：交卷不被跳过阻断，补答范围扩为「被跳过题号的并集」

### 7.1 交卷（B5 / B7 的本意）
`assertComplete` 的排除集合由 `skippedDimensions 展开的题号` 改为 **两个跳过集合的并集**。
被跳过的题**不阻塞交卷** —— 否则「不愿回答」是一个假选项（用户被迫答题才能看到报告），与 B7 的立法目的相悖。

### 7.2 补答（B7「允许事后补答」/ A-4）
| 项 | 现状 | 本 ADR 改为 |
|---|---|---|
| 补答范围 | `cache.skipped`（维度） | `skippedDimensions` 展开的题号 **∪** `skippedQuestionCodes` |
| 提交约束 | 必须一次补齐**该维度**全部题目 | **保持「一次补齐」约束不变**，范围换成「全部被跳过题号」 |
| 越界答案 | 一律丢弃（B5 唯一例外通道） | 不变 |
| 补答后 | `skippedDimensionsJson = []`，`supplemented = pending` | `skippedDimensionsJson = []` **且** `skippedQuestionsJson = []`；`supplemented` = 本次补答涉及的**维度编码**（保持维度级，端上仍标「补测」） |

- **保留「一次补齐」的理由**：避免出现「维度被补了一半」的中间态（该中间态会让 `answeredCount` 的语义与报告文案都变得含糊），且不构成 UX 退步 —— 逐题跳过的用户面临的是「补齐自己跳过的那几题」。
- 补答完成后，两个集合都清空 → 该维度恢复为「已评估」，`evaluated = true`（需 `score !== null`，见决策 3：补齐后必然有有效作答）。
- 补答响应 `data` 仍同 §12.6。

## 八、决策 7：端上交互（落实「敏感题琥珀提示条 + 逐题出口」）

| 环节 | 形态 |
|---|---|
| 进入敏感维度前 | **保留阻断式同意弹窗**（B7 硬性要求：须**就地在答题页**单独勾选同意，不得降级为提示条，也不得改为「去别的页面看说明」） |
| 弹窗选「不同意」 | 该维度整体进 `skippedDimensions`（既有行为不变） |
| 同意后进入维度 | **每题**顶部叠加琥珀提示条（`$zb-color-warning` #D9A441 + 新增浅底 token），文案为「这道题比较私密，你可以选择不回答」+ 右侧「不愿回答」文字按钮 |
| 点「不愿回答」 | 该题号进 `skippedQuestionCodes` 并自动跳下一题；题目卡片进入「已跳过」态，提供「改主意，回答这题」（撤销即在本地集合中移除，随下次草稿提交同步） |
| 交卷前 | 若存在跳过题：中性提示「有 N 题你选择了不回答，将不计入该维度的得分，也不影响你查看报告」 |
| 维度作答进度 | 进度条分母按**两个跳过集合**扣除后计算（与服务端 `buildProgress` 口径一致） |

### 关键约束
- **不得因跳过而阻断交卷**（见 7.1）。
- **不得在提示条里出现任何关系判词**（P7 禁词清单，constitution.md 第 195 行）。
- 逐题跳过的题号**不上报到对方可见的任何端上视图**（见决策 5）。

## 十、后果与风险

| 风险 | 缓解 |
|---|---|
| 用户把「逐题跳过」当成省事路径，大面积跳过敏感题 | 只开放**维度 8 的 8 道题**（白名单死约束）；跳过越多，该维度越可能判为未评估，用户自己拿不到这部分内容 —— 动机上不鼓励滥用 |
| 「零作答 → 未评估」让用户以为系统出错 | 端上对未评估维度给明确中性文案（「这部分你选择了不回答，因此没有结果」），不展示空雷达轴 |
| 引擎 `score` 类型改 `number \| null` 波及其他调用方 | 全仓 `score` 消费点只有 `diff.engine.toScoreMap`（L100 已有 `Number.isFinite` 守卫）与 `double-report-generator`（L182 已过滤）+ 报告渲染；`scoredCount` 语义不变。改动需全量跑 `npm test` |
| 补答「一次补齐并集」在跳过题较多时略重 | 上限即维度 8 的 8 道题 + 至多一个整维（不重叠），最多 8 题一屏可容纳 |
| 维度级与题级两套跳过语义并存，后续维护容易混淆 | 两者字段相邻、注释互指；`resolveSkipped` / `resolveSkippedQuestions` 各自 fail-closed；spec 覆盖交集拒绝 |
