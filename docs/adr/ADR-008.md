## 一、背景

ADR-007 已定「用户点击生成 / DeepSeek / 单人版降级」，但落地 §9.2 prompt 模板时发现 **「输入」段的 5 个占位符里有 4 个的数据来源规格从未定义**：

| # | 占位符 | 规格原文 | 缺口 |
|---|---|---|---|
| 1 | `{typeA}` / `{typeB}`「人格类型」 | 「甲方（发起方）：人格类型 {typeA}（如：**逻辑优先型**）」 | 「逻辑优先型」是 16 型 **维度 C 决策风格**的端点名（constitution L448「决策风格（逻辑优先 ↔ 感受优先）」），而产品里 16 型的**类型名**是「守序者 / 领航者」等 16 个（`P16_TYPE_NAMES`）。示例与产品命名体系对不上；且 16 型 `isScored = false`，**不产出 0-100 维度分**，无法充当 `{scoreA}` |
| 2 | 「**该**维度得分」 | 「该维度得分：甲方 {scoreA}/100…差值 {diff}」 | 议题可挂多维度（如 `long_distance` 挂 CAREER + INTIMACY，ADR-007 附带决策 4），规格未说 `该维度` 指哪一个 |
| 3 | 「分歧**最大**的题目」 | 「分歧最大的题目：{question_text}」 | 未说是在所选维度内取最大，还是全报告取最大 |
| 4 | 「降级为通用版」 | §9.3「校验失败自动重试 1 次，再失败**降级为通用版**并记录」 | 「通用版」内容是什么，规格未定义 |
| 5 | **单人版专属卡的缓存键** | §9.3「同一**邀请**同一议题只生成一次」；schema.sql `exclusive_card` 唯一键为 `(invite_id, topic_id)` | 单人版没有邀请。ADR-007 决策 4 提议「invite_id 降级为 0」→ 全站所有单人用户在同一议题上共用**同一行**，后生成者覆盖前者，**用户会看到别人的专属建议**（隐私事故） |

> 这 5 处皆属「规格没写清」，按 prompt.md 铁律第 2 条，**列出选项交产品负责人裁决**，不擅自发明。

## 二、决策 1：`{typeA}/{typeB}` = 16 型**类型名 + 决策风格端点**

### 选项
| 选项 | 说明 |
|---|---|
| A. **类型名 + 决策风格端点** | 注入形如「守序者（决策风格：感受优先）」 |
| B. 只用 16 型类型名 | 注入形如「守序者」 |
| C. 只用决策风格端点名 | 注入形如「感受优先型」 |
| D. 不注入人格类型 | prompt 只用实测维度分与分歧题 |

### 决定
**采用 A（产品负责人裁决）。**

- 理由：§9.2 的「输出要求」第 2 条明确要求「给甲方 2 句『为乙方量身定制』的开场话术（**符合乙方的决策风格**）」—— 模型必须拿到决策风格轴才能做到；同时「输出要求」第 1 条要求「结合**人格类型**与分歧题」，故类型名也不能省。
- 端点名是**新增常量**（`scale.constants.ts` 的 `P16_POLE_LABELS`），逐字取自 constitution L425-L469 的表头括号说明（如「决策风格（逻辑优先 ↔ 感受优先）」），**不改动任何既有题库文案**。
- 取数来源：该用户**最近一次已交卷**的 `answer_sheet`（`scene = 'p16'`）的 `dimension_scores_json.p16`。
- **未做 16 型测评时不编造**：整行省略，prompt 里不出现 `{typeA}`（见决策 4 的通用原则「宁缺勿造」）。

## 三、决策 2：「该维度」= 议题挂载维度中**差值最大**的那个

### 选项
| 选项 | 说明 |
|---|---|
| A. **取差值最大的挂载维度** | 与「分歧最大」语义一致，专属建议落在最需要谈的点上 |
| B. 按 `mount_dimensions` 顺序取第一个 | 可预期，但可能不是真正的分歧点 |
| C. 注入全部挂载维度 | 信息最全，但 prompt 变长、模型发散，且输出限 180-250 字 |

### 决定
**采用 A（产品负责人裁决）。**

- 判定口径：在议题的 `mountDimensions` 里，取该维度**绝对差 `gap` 最大**者；差值相同则取 `mount_dimensions` 顺序靠前者（保证同一输入必得同一结果，便于复现）。
- 该维度**任一方未评估**时跳过（ADR-005 决策 7：未评估不参与比对，也不参与专属卡），继续在剩余挂载维度里挑；全部未评估则该议题**不具备生成条件**，接口返回降级结果并记 `status = 'degraded'`。
- 议题只挂一个维度时行为与规格字面一致，无变化。

## 四、决策 3：「分歧最大的题目」= **所选维度内**分差最大的量表题

### 选项
| 选项 | 说明 |
|---|---|
| A. **所选维度内分差最大的量表题** | 与「该维度得分」同上下文，模型能顺着一条线讲 |
| B. 全报告分差最大的题（不限维度） | 分差绝对值最大，但可能与「该维度得分」不是同一个维度，上下文割裂 |

### 决定
**采用 A（产品负责人裁决）。**

- 取数来源：`report.flagged_items_json.scale`（R2 已按维度分组、每维度按分差降序取前 2）里 `dimensionCode = 所选维度` 的条目。
- **实现口径细化（2026-09-19 落地时补充）**：报告侧的「按分差降序取前 2」是跨模块排序约定，专属卡**不依赖**它 —— 本服务对候选条目**显式再排序一次**（`gap` 降序）后取第一条，以免报告侧调整取数条数或顺序时这里静默取到另一题。
  排序后取的是**「两端选项文案（`optionLabelA`/`optionLabelB`）齐备」的第一条**：若分差最大者缺任一端文案（历史报告或选项已下架），顺延取下一条齐备者。
- 该维度**无量表题分歧**（或分歧项**全部**缺选项文案）时：**整段省略**（不退回全报告最大值 —— 那会让「该维度得分」与「分歧题」指向两个不同维度，属自相矛盾）。模型只按维度分与人格类型生成。
- `{answerA}` / `{answerB}` 取该条目的 `optionLabelA` / `optionLabelB`；`{question_text}` 取 `questionTitle`。

## 五、决策 4：降级内容 = **该议题的认知卡 + 行动卡拼装**

### 选项
| 选项 | 说明 |
|---|---|
| A. **议题认知卡 + 行动卡拼装** | 从 `topic_card` 取该议题认知卡与行动卡正文拼成一段通用建议 |
| B. 新增 8 段写死的通用兜底文案 | 文案可控，但需新增运营文案且与用户实际分歧无关 |
| C. 不展示专属卡，只提示稍后再试 | 最简单，但违背「降级为通用版」语义 |

### 决定
**采用 A（产品负责人裁决）。**

- 拼装规则：`认知卡 body`（为什么这么谈）+ `行动卡 body`（今晚做什么），按 `order_no` 升序，用换行连接；落 `exclusive_card.content`，`status = 'degraded'`。
- 为什么选拼装：这两类卡的正文**已在 `topic_card` 里、已过 P7 审校、且与议题强相关**——零新增文案风险，且用户看到的仍是有用的内容而非报错。
- 该议题**没有认知卡或行动卡**时（运营删过卡）：只拼现有的那部分；两者都没有才回落到「稍后再试」文案（此路径在实际种子数据下不可达，作为兜底）。
- 降级结果**同样落库缓存**（`uk_owner_scope_topic`，见决策 5）：同一归属方同一议题不反复重试模型；用户后续可手动重新生成（ADR-007 决策 4 的覆盖规则不变）。
  - **例外（2026-09-19 落地时补充）**：上述「两者都没有」的兜底分支写 `status = 'rejected'` 且 **不落库**。理由：该分支产出的 `content` 为空，一旦落库，后续读取会命中「有缓存行但无内容」→ 用户永久停在「无内容且不再重试」的死角。不落库则下次点击会重新走一次生成（此时成本仅一次禁词/取数判定，不产生模型调用异常放大）。
- 降级原因写 `check_result`（`reason = 'llm_unavailable' / 'sensitive_rejected' / 'no_dimension_data'` / `'model_error'`），命中词一并记录，**模型原文不落库、不下发**。

## 六、决策 5：`exclusive_card` 增加 `owner_uid`，缓存键改为「归属 + 邀请 + 议题」

### 选项
| 选项 | 说明 |
|---|---|
| A. **加 `owner_uid` 列** | 唯一键改 `(owner_uid, invite_id, topic_id)`：双人版 `owner_uid` = 发起方 uid、`invite_id` = 真实邀请；单人版 `owner_uid` = 本人 uid、`invite_id` = 0 |
| B. 单人版不落库不缓存 | 每次点击重新调模型。零 schema 变更，但单人用户反复点会反复产生模型开销 |
| C. 单人版缓存放 Redis | key 含 userId、TTL 24h。零 schema 变更，但同一概念两套存储，缓存不可查、被淘汰后需重新生成 |

### 决定
**采用 A（产品负责人裁决）。**

- 为什么不能沿用 ADR-007 决策 4 的「invite_id = 0」：唯一键 `(invite_id, topic_id)` 会让**全站所有单人用户在同一议题上共用同一行**，第二个生成者覆盖第一个人的 `content` —— 这是把 A 用户的专属建议展示给 B 用户，属**隐私事故**，不是缓存效率问题。
- 归属口径：
  - **双人版**：`owner_uid = invite.initiator_uid`（⚠️ 不是 `requester_uid`）。规格要求「同一**邀请**同一议题只生成一次」，发起方与被邀请方分别点击时应命中同一张卡，故归属必须是**邀请**而不是点击者；`requester_uid` 继续承担「谁触发的」审计语义。
  - **单人版**：`owner_uid = 本人 uid`，`invite_id = 0`。
- 单人在完成邀请后**不迁移、不合并**已有单人卡：双人版是另一行（`owner_uid`/`invite_id` 都不同），端上按「有就绪报告 → 请求双人版」自然取到新卡；旧单人卡保留作为历史。这与 ADR-007 决策 4「不自动改写已生成内容」一致。
- **schema 变更（本 ADR 唯一一处）**：`docs/schema.sql` 的 `exclusive_card` 增加 `owner_uid` 列，唯一键 `uk_invite_topic` → `uk_owner_scope_topic`。该表在模块 7 上线前**为空**，服务器迁移只需重建这一张表（见 §十）。

## 七、附带技术决策

| # | 议题 | 决定 | 依据 |
|---|---|---|---|
| 1 | 禁词校验与重试 | 每次生成最多调模型 **2 次**（首次 + 重试 1 次），两次均命中禁词或失败才降级 | §9.3 字面 |
| 2 | 降级是否算「已生成」 | 算。`exclusive_card` 行照常写入（`status = 'degraded'`），缓存生效 | 避免用户每次进议题都触发一次模型调用 |
| 3 | 解锁判定 | 接口返回 `locked`；P1 `PAYMENT_GATEWAY=free` 下 `EntitlementService` 恒为已解锁。端上按 `locked` 决定「锁形占位 + 价格」还是「生成按钮」 | §9.1 / §9.4；P2 上线零端上改动 |
| 4 | 单人版 `{typeB}` | 单人版 prompt **不含乙方段落**（不是填空），从模板结构上去掉，避免模型凭空补一个「对方」 | ADR-007 决策 4「单人版不编造对方数据」 |
| 5 | 阅读进度 | 服务端记录（`topic_read_progress`），随交卷/滑动上报 | ADR-007 附带决策 3 |
| 6 | 审计 | 每次**真实调用模型**（含降级）写 `audit_log`：`action = 'exclusive_card_generate'`，`actor_type = 'user'`，`target_type = 'exclusive_card'`，`detail = {inviteId, topicCode, promptVersion, model, status, reason}` | §9.3；schema.sql L540 已把 `exclusive_card_generate` 列为该表 action 示例 |
| 7 | LLM 调用方式 | 直连 `POST {LLM_API_BASE}/chat/completions`（OpenAI 兼容），不引厂商 SDK；超时 20s，`temperature` 低值以稳定输出 | ADR-007 决策 3 |
| 8 | **单人版「该维度」口径** | 取议题 `mount_dimensions` 顺序**第一个已评估**的维度；全部未评估则不具备生成条件，降级并记 `reason = 'no_dimension_data'` | 2026-09-19 产品负责人裁决。决策 2 只定义了双人版（差值最大者），单人版无差值可比；取「顺序靠前者」与决策 2 的 tie-break 同源，保证同一输入必得同一结果 |
| 9 | **重新生成覆盖缓存的频次上限** | 仅「输入升级」时可覆盖：缓存为 `premium-v1-solo` 且当前已有就绪双人报告时，点击即重新生成并覆盖为 `premium-v1-duo`；其余情况**直读缓存**（幂等，不再调模型） | 2026-09-19 产品负责人裁决。ADR-007 决策 4 要求「可手动重新生成覆盖缓存」，其风险表又要求控成本；本规则把成本上界锁死为「每归属方每议题最多 2 次调用」（1 次 solo + 1 次 duo），且降级结果不会被反复重试模型 |

## 九、后果与风险

| 风险 | 缓解 |
|---|---|
| 用户未做 16 型测评 → prompt 缺人格类型，输出泛化 | 视为正常输入缺失（不是失败）：提示语仅按维度分与分歧题生成；端上不提示「请先做 16 型」（避免用内容功能反向逼测） |
| 「差值最大的挂载维度」与用户主观感受的分歧点不一致 | 议题包内容本身覆盖该议题的主流分歧点；专属卡只是**开口话术**，不承担全面诊断职责 |
| 降级内容与专属卡观感差异大 | 降级时端上仍展示卡片（不显示「生成失败」），`status` 只落库不外显（避免用户感到被降级对待） |
| 模型被诱导输出禁词 | 生成后过 `SensitiveWordService(scope = 'exclusive_card')`；两次不过即降级，原文不落库不下发 |
| **单人卡缓存串号（隐私）** | 由 `uk_owner_scope_topic(owner_uid, invite_id, topic_id)` 在**库层面**保证：查询与写入都带 `owner_uid`，不依赖应用层过滤；回归单测覆盖「两个单人用户同一议题互不可见」 |

## 十、迁移与运维

- **schema 变更 1 处**（`exclusive_card`，模块 7 上线前该表为空，安全）：
  ```bash
  # 在服务器上执行（容器内 mysql 必须显式 utf8mb4，见 schema.sql 头部说明）
  docker compose exec -T mysql mysql --default-character-set=utf8mb4 -uroot -p"$DB_ROOT_PASSWORD" zhiban <<'SQL'
  DROP TABLE IF EXISTS `exclusive_card`;
  CREATE TABLE `exclusive_card` (
    `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    `owner_uid`       BIGINT UNSIGNED NOT NULL,
    `invite_id`       BIGINT UNSIGNED NOT NULL,
    `topic_id`        BIGINT UNSIGNED NOT NULL,
    `requester_uid`   BIGINT UNSIGNED NOT NULL,
    `content`         TEXT            DEFAULT NULL,
    `status`          VARCHAR(16)     NOT NULL DEFAULT 'pending',
    `prompt_version`  VARCHAR(16)     NOT NULL,
    `model`           VARCHAR(64)     DEFAULT NULL,
    `check_result`    JSON            DEFAULT NULL,
    `generated_at`    DATETIME        DEFAULT NULL,
    `created_at`      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_owner_scope_topic` (`owner_uid`, `invite_id`, `topic_id`),
    KEY `idx_status` (`status`)
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI 个性化专属卡（生成一次缓存）';
  SQL
  ```
  ⚠️ 不要直接重跑整个 `docs/schema.sql`（它含全库 `DROP TABLE`，会清掉用户与邀请数据）。
- 其余 8 张表（`topic` / `topic_card` / `topic_read_progress` / `audit_log` / `report` / `answer_snapshot` / `answer_sheet` / `invite`）**无变更**。
- 端点名常量改动属**题库元数据**（非题面），不需要重跑题库种子。
- `LLM_API_KEY` 未配置时专属卡**直接降级**（不报错、不阻塞内容浏览）：`status = 'degraded'`，原因 `llm_unavailable`。
