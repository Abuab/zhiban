# 《婚前关系准备评估》小程序 · 产品宪章与开发规范 v0.1

> 文档性质：Constitution（宪章）+ 约束规范 + Spec Kit 流程定义

## 第一部分：产品宪章（Constitution）

### 1.1 愿景与定位

为处于"谈婚论嫁"阶段的情侣与认真相亲的单身用户，提供一套**基于自评量表的关系准备度评估工具**与**关系沟通能力学习内容**，帮助用户在婚前系统性地看见彼此、谈清分歧。

**一句话定位**：婚前关系准备的"自测仪表盘" + 沟通能力的"自习室"。

**不是什么（Non-Goals，永久禁止项）**：
- ❌ 不是婚恋交友/相亲撮合平台（不碰社交类目红线）
- ❌ 不是心理咨询/诊疗服务（不碰医疗资质红线）
- ❌ 不是算命占卜/星座八字/配对玄学（不碰封建迷信红线）
- ❌ 不做 UGC 社区、不做用户间私信、不做直播/连麦咨询撮合

### 1.2 核心原则（按优先级排序）

| 编号 | 原则 | 含义 | 落地要求 |
|---|---|---|---|
| P1 | 合规先于增长 | 任何功能上线前必须先过合规检查清单 | 每份 PRD 附《合规自检表》；驳回权归合规负责人 |
| P2 | 测评质量即产品 | 用户觉得"准、像我、有用"是复购与推荐的唯一来源 | 每次发版前 ≥10 对真实用户试测；报告文案人工打磨 |
| P3 | 隐私即卖点 | 婚恋观、亲密观属高敏感数据，泄露即品牌死亡 | 数据最小化、双人数据仅双方可见、可随时注销清空 |
| P4 | 免费优先，商业化后置 | 前期用免费积累种子用户与口碑，不急于收费 | P1 阶段全免费；付费功能须老板书面确认后立项 |
| P5 | 内容与规则可配置 | 题目、维度、计分、报告文案全部后台可配 | 任何硬编码进代码的题/文案 = 工程事故 |
| P6 | 一人可运营 | 后台轻量，日常运营不依赖专职团队 | 管理后台功能以"够用"为限，拒绝过度设计 |

### 1.3 决策与变更机制

- 宪章修改：仅产品负责人可发起，需书面记录变更理由（走 ADR 流程）。
- PRD 与宪章冲突：停止开发，先改 PRD 或发起宪章变更。
- 所有架构级决策必须写 ADR（架构决策记录），存 `/specs/adr/`。

## 第二部分：合规约束规范（微信审核与资质边界）

> 本部分为强制约束。主体：个体工商户（信息咨询类经营范围），后续可升级有限公司 + ICP 证扩展社交类目，但当前版本一律按个体户边界设计。

### 2.1 资质与类目约束

| 项 | 约束 |
|---|---|
| 主体 | 个体工商户营业执照（经营范围含：信息咨询服务、教育咨询） |
| 小程序类目 | 仅可使用【工具】+【教育-教育信息服务】，ICP 备案完成后提审 |
| 禁止类目 | 社交-婚恋、医疗、心理（任何沾边的都不选） |
| ICP | 备案（非经营性）小程序后台提交；ICP 证（经营性）为 P3 之后事项，当前版本不涉及 |
| 内容审核 | 全部题目/课程文案属平台责任内容，上架前逐条过审；不做用户发布 |

### 2.2 命名与文案红线

| 红线 | 要求 |
|---|---|
| 商标规避 | 全文禁止出现 "MBTI"、"DISC"、"大五人格/NEO" 等受保护名称与官方类型代号（INTJ 等）。使用自研命名："**16 型人格图谱**"，类型代号自造（如 指挥家/守护者…） |
| 诊断类词汇 | 禁止"诊断/检测/鉴定/测出你有 XX 症/障碍"。统一用"自评/探索/倾向/画像" |
| 玄学类词汇 | 禁止"配对指数/缘分/八字/星座/合盘/旺" |
| 医疗类词汇 | 禁止"治疗/疗愈/咨询（心理咨询含义）/干预"。课程叫"沟通课/关系课" |
| 效果承诺 | 禁止"保证婚姻幸福/避免离婚"等承诺性表述 |

### 2.3 必备文案（每个报告页脚固定）

> 本测评基于自评量表，结果仅供自我了解与伴侣沟通参考，不构成心理学诊断、心理咨询或婚姻法律建议。

### 2.4 数据与隐私约束

- 启动即弹《隐私政策》，不同意则仅可浏览首页。
- 注册时年龄确认：**未满 18 岁不可使用**（婚恋场景属性）。
- 高敏感题目维度（性与亲密观）须单独勾选同意后才进入答题。
- 双人数据：任何一方报告仅本人可见；对比报告需双方各自授权生成。
- 数据存储境内；注销账号 = 物理删除答题数据（不软删）。
- 最小化：不收集真实姓名、身份证号、通讯录、精确位置。

### 2.5 支付约束（当前版本）

- P1 阶段：全免费，不接支付。
- 付费功能上线前需单独评审，且必须解决 iOS 虚拟商品支付合规问题（当前 iOS 端小程序虚拟内容支付受限，方案未定前 Android 先行或采用实体权益卡/兑换码模式）。
- 禁止诱导分享后强制解锁（微信明确违规点）：分享可以，不能"不分享不给看结果"。

| color-primary-dark | #C95A34 | 按下态 |

| radius-card | 16rpx | 卡片圆角 |

### 4.3 关键体验原则

1. **答题要有进度感**（进度条 + 题数），中途退出自动保存。

3. **分享卡片即广告**：分享图设计单独评审（微信分享卡片是核心裂变载体）。
4. 全端遵循《微信小程序设计指南》，字号不小于 28rpx 正文基准，支持系统字体放大。

# 规范增补 v0.2：内容基调、外部方法论与报告可见性

> 性质：对《constitution-v0.1》的增补，经产品负责人确认后与宪章同效。
> 涉及宪章条款修订：P2（测评质量）补充内容基调；新增 P7（内容基调）；第三部分修订 2.4 隐私条款。

---

## 一、新增原则 P7：劝和不劝离（内容与报告铁律）

1. **禁用判词**：全文（题目、报告、锦囊、分享文案）禁止出现——"不合适""不匹配""危险信号（用于关系判断时）""劝分""重新考虑这段感情""离婚风险 X%"等关系否定或量化风险表述。
2. **中性命名**：双人差值 >30 的区域命名为"**待沟通区**"；逐题分歧清单命名为"**值得一起聊聊的事**"。
3. **话术方向**：所有差异输出必须配套"怎么谈"的建议，不给"要不要继续"的建议。报告结构强制：先给共识区（肯定），再给待沟通区（配对话建议）。
4. **底线例外（劝和不和稀泥）**：题库设"底线确认"独立题组（3-5 题），覆盖：隐瞒婚史、赌博/吸毒恶习、暴力倾向、大额隐瞒负债、征信严重不良。触发任一 → 报告输出独立中性提示："这部分个人事实，建议在关系进入下一步前充分核实与确认。" 不输出关系判词，不引导分手。

## 二、内容方法论：吸收自媒体相亲专家经验（引用规范）

### 2.1 必须吸收的三件套
- **案例化开场**：每篇锦囊以"具体场景对话"切入（不超过 120 字），拒绝理论开头。
- **话术化交付**：每篇至少给出 3 条可直接照说的原话，标注适用场景与禁忌。
- **反套路结构**：先指出 1-2 个常见翻车做法（用户产生"这就是我"的代入感），再给替代方案。

### 2.2 明令禁止（品牌与审核红线）
- 禁止性别对立叙事（"男人都/女人都"句式）、群体贬损
- 禁止 PUA/操控话术（打压、欲擒故纵、情感操控类"技巧"）
- 禁止焦虑营销（"再不做就晚了""不改就等着分手"）
- 禁止绝对化承诺（"说了这句话 TA 一定……"）
- 禁止搬运任何创作者原创内容；只吸收方法论，案例全部原创虚构

## 三、双人对比报告可见性规范（修订 2.4）

### 3.1 三层可见模型
| 层级 | 对象 | 内容 |
|---|---|---|
| L1 完整版 | 发起方（付费方） | 双人雷达图、各维度差值、待沟通区明细、逐题分歧、锦囊入口 |
| L2 基础版 | 被邀请方 | 共同完成纪念卡、共识区内容（仅正向）、"有些话想和你聊聊"入口 |
| L3 分享版 | 由发起方生成 | 可勾选内容的分享长图（默认仅含共识区与正向建议），发起方决定是否发给对方 |

### 3.2 强制规则
1. 被邀请方**不可见**：任何维度差值、分歧题目、对方单人答案。
2. 双方答题前均须勾选知情同意："你们的答案将共同生成一份关系分析；详细分析由发起人持有，你可见基础摘要。"
3. 被邀请方解锁完整版 = 独立付费点（与发起方同价），双方付费互不可见对方购买行为。
4. 对方未完成答题时，发起方仅可见"待对方完成"状态，不得单方生成任何对比结论。

### 3.3 隐私政策同步修订
- 新增条款：说明双人数据的持有关系（详细分析归发起方）、被邀请方的可见范围、解锁机制。

# 规范增补 v0.3：内容形态重构（替代长文锦囊标准）

## 背景
长文锦囊形态作废（用户无耐心读完；通用 AI 可提供同类内容，无护城河）。
新护城河 = **双方测评数据 × 个性化生成**，通用 AI 不具备用户的双人答案快照。

## 一、微内容标准（替代《价值感与内容标准》中锦囊部分）

1. 议题包 = 8-12 张卡片流；每张卡只承担一个功能，≤120 字。
2. 必含：坑卡 ≥2、话术卡 ≥3（长按复制）、**演练卡 ≥1**（情景选择题，选错有解析）。
3. 读完整个议题包 ≤3 分钟；全文案口语化，禁止说教腔。
4. 演练卡选项设计原则：每个错误选项对应一个真实翻车理由，解析比选项长不了多少。

## 二、AI 个性化专属卡（护城河机制）

- 专属卡由服务端调用大模型 API 生成；prompt 注入：双方维度得分、16 型类型、分歧题目及双方选项。
- 同一份邀请只生成一次并缓存（控成本）；题库/模板升级不溯及已生成内容。
- 生成结果须过一次敏感词与合规校验（P7 禁词清单）后才展示。
- 成本控制：专属卡生成仅在付费解锁后触发；免费用户见通用卡 + 锁定占位。

## 三、付费价值重构

付费购买的不是"内容"，是"**只属于你们俩的版本**"：
- ¥6 = 议题卡包 + 专属卡生成一次
- 报告中每个待沟通区 → 对应议题包入口，天然衔接

## 四、对既有文件的修订
- 《价值感与内容标准-v0.1》第二节"相处锦囊"指标作废，以本文件为准。
- 报告价值感指标（7 项硬指标）不变。
- 首批交付物改为：8 个议题的卡片流脚本 + 专属卡 prompt 模板（由 AI 起草、人工审校）。

## 第三部分：计分与判定规则

1. **量表题**：很不同意=1 … 很同意=5；反向题翻转（6-原值）。
2. **维度分** = 该维度量表题（含反向处理后）均分 × 25 → 0-100 分。风格题（Q27）不计入。
3. **选择题**（Q3/Q37/Q38）：不参与维度分，作为**分歧比对题**：两人选项不同即记为分歧题。
4. **逐题分歧**：量表题同题 |分差| ≥3 记为分歧题；选择题选项不同记为分歧题。每维度按分差降序取前 2 题进入报告。
5. **差值分级**（后台可配）：<15 高共识 / 15-30 待沟通 / >30 重点待沟通（D6：恰在阈值归入较低一级）。
6. **底线组**：任一题答 1-2 分 → 触发核实提示（见第一部分末）。
7. **作答质量**（B3/B4）：总时长 <3 分钟或全部同值 → 低质量标记，报告正常生成但附"结果可能受作答状态影响"提示。
8. **16 型计分**：每维度 6 题，统计 A 端选择数：≥4 取 A 端，≤2 取 B 端，=3 时取该维度中点偏向（记录平局标记）。四维度组合映射类型名。

## 第四部分：版本与治理
- 量表版本号 SCALE-PRE-1.0；邀请创建即锁定版本快照（B8 边界规则）。
- 题目级开关：任一题可单独下架，新邀请用新版本，进行中邀请不受影响（G1）。
- 试测信度目标：同一用户间隔 2 周重测，同维度相关 ≥0.7 方可标 frozen。

> 定位：本文件优先级等同宪章原则。所有报告与锦囊内容须逐条对照执行。

## 一、内容详实度硬指标

### 付费版对比报告（¥8 解锁）
| 项 | 标准 | 简版对照（免费） |
|---|---|---|
| 维度解读 | 每维度 300-500 字：分数含义 + 你们这分数常见原因 + 1 个具体情境 | 一句话点评 ≤30 字 |
| 对话建议 | 每维度 ≥3 条可直接开口的问题原话 | 无 |
| 待沟通区 | 逐题呈现分歧 + 各自答案 + 中立分析 + 怎么谈 | 仅标记维度名 |
| 共识区 | 逐条列出你们一致的答案原文（给糖） | 仅分数 |
| 专属感 | 嵌入两人昵称，全文"你们"称谓 | 无昵称 |
| 仪式感 | 生成动效（雷达图展开）→ 可保存"证书级"长图 | 静态图 |
| 结尾 | 一段 150 字"写给你们的"总结文案 | 无 |

### 相处锦囊（¥6/篇）
- 篇幅 ≥2000 字；结构 = 场景还原（≤120字）→ 翻车现场 ×2 → 正确打开方式 → 话术原话 ×3（标注适用场景与禁忌）→ 16 型人格适配提示 → 一页行动清单（今晚能做）
- 排版按"杂志专题"标准：对话用气泡样式、重点句提色、每屏一个焦点

## 二、UI 精美标准（UX-001 增补）

1. **杂志级排版**：报告页像一本婚育杂志的内页，不是表单。大留白、字体层级 ≥5 级、每屏一个视觉焦点。
2. **插画体系**：8 个维度各配一套同风格插画（温暖扁平风），禁止用素材站通用商务图。
3. **动效**：报告生成 = 雷达图逐维度点亮动画（≤2 秒，可跳过）；解锁 = 纸张展开动效。
4. **证书级长图**：保存分享的长图按"纪念证书"设计（囍印/边框/两人昵称/日期），这是裂变物料也是付费价值的实体化。
5. 分享卡片（微信好友卡片图）单独评审，首图只出现"你们已共同完成 X 项共识"正向文案，不出现分数。

## 三、"值"的心理设计

1. 付费瞬间：解锁动效 + "已生成你们的专属报告"——让 8 元感觉像开启一份礼物。
2. 信息差可视化：简版与完整版同页面对比展示锁定内容清单（不展示内容，只展示"8 个维度深度解读 / 23 条对话建议 / 你们的一致清单"数量）。
3. 收藏感：报告可保存、可回看；锦囊有"已学会"打卡。

# PRD-002 双人共同测评与对比报告 v0.1（draft）

## 1. 概述
付费方完成单人测评后，可付费发起"双人共同测评"，邀请伴侣/交往对象独立完成同一量表，系统生成双人对比报告。核心逻辑：差值不评判对错，只标记"待沟通区"并配对话建议。

## 2. 名词
- 发起方：付费并发起邀请的用户
- 被邀请方：通过分享卡片进入的用户
- 量表：婚前准备评估 v1.0（8 维度 70 题，见题库规范）
- 答案快照：邀请创建时锁定量表版本，双方答同一快照，防题目改版导致差值失真

## 3. 邀请状态机
```
none → invite_created（发起方已付¥8，生成邀请码+分享卡片）
     → invite_opened（被邀请方打开，弹知情同意页）
     → consent_given → answering（答题中，断点续答）
     → completed（被邀请方交卷）
     → report_unlocked（系统校验双方答案齐备 → 生成对比报告 → 发起方解锁完整版，被邀请方解锁基础版）
异常分支：
- 30 天未 completed → expired（不退款，可续期 7 天一次）
- 发起方主动取消 → cancelled（¥8 不退，防恶意试探他人答案）
- 被邀请方拒绝同意 → declined（发起方可重新邀请他人，限 1 次换人）
- 被邀请方此前已完成过同版本单人测评 → 询问其"复用答案或重答"（复用需其确认授权）
```

## 4. 核心规则
- R1 差值计算：各维度分别计算双方均分，取绝对差。分级阈值后台可配（默认 <15 高共识 / 15-30 待沟通 / >30 重点待沟通），评级命名不得出现否定性词汇（P7）。
- R2 逐题分歧：同题答案差 ≥3（5点量表）标记为分歧题；每维度最多呈现 2 题，按分差降序。
- R3 可见性（三层，见规范增补 v0.2 第三节）：
  - 完整版（发起方）：雷达图、差值、待沟通区、分歧题、锦囊入口
  - 基础版（被邀请方）：纪念卡、共识区（仅正向）、无差值无分歧
  - 分享版（发起方生成，可勾选，默认仅共识区）
- R4 双方答案互不可见：任何一方均看不到对方单人原始答案。
- R5 底线题组（R0）：触发时向**双方**同时提示"部分个人事实建议在关系进入下一步前充分核实"，但不含关系判词。
- R6 报告生成时机：双方 completed 后异步生成（队列），正常 ≤10 秒；生成失败自动重试，前端轮询。
- R7 复用答案：被邀请方复用历史答案时，快照标注"复用"，报告正常生成。
- R8 知情同意文案（答题前强制勾选）："你们的答案将共同生成一份关系分析；详细分析由发起人持有，你可见基础摘要。"

## 5. 边界与异常
- 对方不答：发起方仅见状态与"提醒 TA"（订阅消息模板，每邀请限 3 次）
- 一方中途退出：答案保留 7 天，可续答
- 两人答题时间差 >30 天：允许，报告快照版本不变
- 重复购买：同一发起方同时最多 1 个进行中邀请（防囤积），历史报告永久可回看

## 6. 数据模型要点
invite(id, initiator_uid, invitee_openid, status, amount, created_at, expire_at, reuse_allowed)
answer_snapshot(invite_id, user_uid, scale_version, answers_json, completed_at, is_reuse)
report(invite_id, dimension_scores_json, diffs_json, flagged_items_json, version)
visibility_log(report_id, viewer_uid, level)  —— 审计用

## 7. 接口清单（契约详见 /specs/api）
- POST /invites（创建，含支付）
- GET /invites/:code（被邀请方进入：状态+知情同意）
- POST /invites/:code/consent
- POST /invites/:code/answers（提交/续答）
- GET /invites/:code/report（按 viewer 身份返回对应层级）
- POST /invites/:id/remind
- POST /reports/:id/share-image（生成分享版长图）

## 8. 合规自检（G1）
✅ 无匹配/撮合功能 ✅ 无单方查看对方答案 ✅ 知情同意完备 ✅ 评级命名中性 ✅ 底线题仅提示核实 ✅ 分享版内容由发起方控制、默认仅正向

# PRD-005 支付与权益判定 v0.1

## 1. 权益模型（服务端唯一可信）
```
entitlement(id, user_id, product_id, source, status, granted_at, expire_at)
product: double_invite(¥8) /锦囊单品(¥6)/锦囊合集(¥29.9)
```
- 权益挂在 user（微信 openid 绑定账号）上：换设备、换手机、iOS/Android 切换均不影响
- 前端任何"已解锁"判断必须来自服务端 GET /entitlements，禁止本地缓存作为判定依据

## 2. 入账流程
```
用户调起微信支付 → 服务端预下单（生成 out_trade_no，金额以后端商品表为准，前端传价只作展示）
→ 微信支付 → 微信回调 /pay/notify
→ 服务端验签 → 幂等检查（out_trade_no 已处理则直接返回 success）
→ 写入 entitlement + 事务
→ 前端轮询/订阅消息确认解锁
```
关键：金额、商品、权益以后端配置为准（防篡改）；回调幂等（微信会重复推送）；回调处理失败不得丢单（死信队列+人工补单后台）。

## 3. 进入小程序的判定
启动流程：wx.login → 后端换 openid → 查 user → GET /entitlements → 前端按权益渲染。
- 打开报告页/锦囊页时二次校验（防止链接分享绕过）
- 未登录态：一切付费内容视为未购

## 4. iOS 策略
- iOS 端隐藏所有购买按钮（商品表配置 ios_visible=false）
- iOS 用户可见锁定态与内容清单；已购权益在 iOS 正常展示（账号级）
- 过渡期解锁路径：客服会话发放兑换码（后端配置码池），兑换码 = entitlement source=coupon

## 5. 退款与客诉
- ¥6/¥8 小额：支持未使用可退（报告未生成全额退，生成后不退）
- 退款 = entitlement 作废 + 微信退款回调幂等

# 基础设施与部署方案 v0.1

## 0. 现有资源核查清单（Blocking，本周完成）

| 资源 | 要求 | 核查动作 |
|---|---|---|
| 4C4G 服务器 | 纯净或可重装 Linux（Ubuntu 22.04 / Debian 12） | 重装系统，不要沿用旧项目环境 |
| 已备案域名 | **备案主体必须与小程序主体一致（你的个体户全称）** | 工信部备案系统查询备案主体名称；若域名挂在别人公司/个人名下 = 不可用，需重新备案到个体户名下 |
| 域名接入商 | 若服务器换到新厂商，需做"变更接入"备案 | 查询当前接入商 |
| 个体户资质 | 经营范围含"信息咨询" | S0 已列入变更 |

> ⚠️ 小程序备案（2023.9 起强制）：微信小程序本身也要备案，在微信公众平台提交，主体=个体户，
> 需填写已备案域名。域名备案主体 ≠ 小程序主体会被驳回。

## 1. 单机部署架构（4C4G）

```
域名(HTTPS)
  └─ Nginx（80/443，反代 + 静态资源 + 限流）
      ├─ NestJS 应用（PM2 守护，2 实例）
      ├─ MySQL 8（测评/订单数据，独立数据盘）
      ├─ Redis（会话缓存、报告缓存、轻量队列）
      └─ 对象存储 COS/OSS（报告长图、插画、分享卡片图——不占服务器磁盘和带宽）
```

- 图片/长图一律走对象存储 + CDN，4C4G 的小水管带宽经不起图片流量
- 证书：Let's Encrypt 免费证书自动续期；Nginx 强制 HTTPS + HSTS

## 2. 容量评估（为什么够用）

测评类小程序特征：写少读多、无实时交互、无大流量场景。
- 单次答题提交 ≈ 15KB；报告读取 ≈ 10KB + 图走 CDN
- 4C4G 单机估算上限：日均 2-5 万 PV、峰值 200 QPS 内无压力
- 达到日均 1 万单之前（年收入 200 万级别）无需扩容
- 扩容路径（预留）：MySQL 迁云数据库 → 应用水平扩 → 队列/报告生成独立

## 3. 数据与容灾（上线前必须就位）

| 项 | 方案 |
|---|---|
| 数据库备份 | 每日凌晨全量 + binlog，备份文件**异地**（另一台机器或对象存储），保留 30 天 |
| 演练 | 每季度恢复演练一次 |
| 报告数据 | 报告内容 JSON 落库 + 长图对象存储双份 |
| 支付对账 | 每日与微信支付对账单核对（防漏单） |

## 4. 安全基线

- 管理后台：独立路径 + IP 白名单 + 账号密码 + 二次验证；后台接口与小程序接口分离鉴权
- 接口：全局 rate limit（按 openid）、微信登录态校验、参数化查询防注入
- 服务器：SSH 禁密码登录（仅密钥）、fail2ban、自动安全更新
- 密钥管理：微信支付证书/密钥放服务器环境变量，禁止进代码库
- 依赖漏洞：每月一次 npm audit

## 5. 成本（月）

服务器已有 ¥0；对象存储+CDN 约 ¥10-30（起量后）；证书 ¥0；备份存储 ¥5-10。

## 〇、配置化设计总原则（架构级约束，写进 ADR-001）

凡满足以下任一条件的，必须做成后台配置项，禁止硬编码：
1. 运营期可能调整（价格、文案、题目、Banner）
2. 不同人群/场景有差异（报告模板分相亲版/备婚版）
3. 需要 A/B 或灰度（解锁免费 vs 付费）

| 量表域 | 测评版本、维度、题目、选项、分值、反向题标记、底线题组开关 | 树形 JSON，版本化 |

## 议题 01｜彩礼：行情是地板，结构才是谈判桌

**卡1｜坑卡**
饭桌上长辈刚提彩礼，你抢着说："现在年轻人不讲究这些。"
💥 一分钟内，对方父母会觉得女儿被"降价处理"。第一分钟的底线：**不当长辈的面否定彩礼话题本身**。

**卡2｜坑卡**
直接还价："18.8 万太多了，10 万行不行？"
💥 砍价式回应把婚事谈成买卖，还顺手贬了对方家乡的规矩。行情地区谈判的对象从来不是数字本身。

**卡3｜认知卡**
行情固化的地区（如 18.8 万+车房+五金），**要谈的不是"给不给"，而是"怎么给"**。
四个可谈变量：金额能否拆、形式怎么算、什么时间给、最后归谁用。数字是死的，结构是活的。

**卡4｜话术卡**（对伴侣，摸底）
"你们那边现在具体什么行情？彩礼、五金、车房都怎么算？咱俩先把'当地标准清单'完整列出来，再看每一项里哪些有空间。"

**卡5｜话术卡**（对伴侣，定调）
"行情我们认，这是诚意。但我想和你商量'怎么给'——是一次到位还是分步，车房写谁、怎么个流程，最后这笔钱落到哪。"

**卡6｜话术卡**（结构方案）
"比如彩礼走全礼数，面子给足；其中约定一部分以嫁妆/小家庭启动金回流；车房计入小家庭资产计划。两家都好看，钱也回到咱们手里。"

**卡7｜演练卡**
对方说："我们那边就是这个价，没什么可谈的。"
A. "行，那就按这个来。"（空间全失，还可能加码）
B. "明白，行情我尊重。那咱们聊聊'怎么给'吧——流程和安排上，应该还有得商量？" ✔
C. "这也太贵了。"（谈判直接破裂）
解析：认行情=认诚意，是打开结构谈判的前提；B 把战场从数字挪到安排。

**卡8｜行动卡**（今晚）
① 各自列：当地行情完整清单（含五金、车房口径）② 标出哪些是"死的"、哪些有弹性 ③ 约好：长辈再问，统一回复"我们俩在商量方案"。

## 议题 02｜管钱：婚前不交底，婚后全是雷

**卡1｜坑卡**
领证后才第一次看到对方的征信和负债。
💥 婚后炸的雷，婚前都是没问出口的问题。财务不透明不是信任问题，是流程问题——**流程可以补，爆炸没法补**。

**卡2｜坑卡**
"谈钱伤感情。"
💥 真相是：不谈钱才伤感情。回避谈钱的关系，最后都靠吵架来谈。

**卡3｜话术卡**（婚前交底）
"我想咱俩在领证前互相交个底：收入、存款、负债、每月给父母的固定支持。不是查岗，是避免婚后炸雷——我先说我的。"

**卡4｜话术卡**（共同账户）
"咱们建一个共同账户，每人每月按收入比例打一笔，家里开销全从里面出，剩下的各自自由支配——各有的花，家也有的花。"

**卡5｜话术卡**（大额规则）
"定个规矩：单笔超过 X 元的大件消费，互相打个招呼。不是请示，是让彼此心里都有数。"

**卡6｜演练卡**
无意中发现对方有一笔没提过的消费贷。
A. "你居然瞒着我借钱？！"（信任直接开战）
B. "我看到了那笔贷款，咱一起捋捋：多少、利率、怎么还，要不要并到共同计划里。" ✔
C. 装不知道，等 TA 自己说。（攒雷）
解析：B 把"隐瞒"处理成"待解决的财务问题"，而不是"人格审判"。

**卡7｜行动卡**
① 交换征信报告（人行官网可查）② 列出各自固定支出表 ③ 确定共同账户比例，先试跑三个月。

## 议题 03｜家务分工：自觉是最不靠谱的分工方式

**卡1｜坑卡**
"谁看不下去谁干。"
💥 结局几乎固定：标准低的一方岁月静好，标准高的一方负重前行——直到某天为一只碗爆炸。

**卡2｜坑卡**
说"帮你做点家务"。
💥 "帮"这个字本身就是坑：默认了家务是某一方的主业。家是两个人的，活也是。

**卡3｜话术卡**（清单分赃）
"把家里所有家务列成清单，一人挑一半，剩下的互相交换——这比'自觉'靠谱一百倍。"

**卡4｜话术卡**（标准对齐）
"你眼里的'收拾好了'和我眼里的可能差很远。先对齐标准再分活——不然我们天天为同一件事吵架。"

**卡5｜话术卡**（动态调整）
"每月留一次 15 分钟'家务例会'：谁最近累、谁最近闲，临时换一换。别让怨气攒到爆发。"

**卡6｜演练卡**
对方说："我工作累，你就多干点呗。"
A. "凭什么？！"（进入对错之争）
B. "累是真的，那这周你少干的，换成你负责 XX 和那两件，下周看你状态再调——行不？" ✔
C. 默默多干，记在心里。（记账式怨气）
解析：B 承认事实 + 按周动态换岗，家务从"义务之争"变"排班问题"。

**卡7｜行动卡**
① 列出全部家务清单（含隐形劳动：采买、记账、记亲戚生日）② 各自认领 + 交换 ③ 手机上共享待办，完成打勾。

## 议题 04｜二胎分歧：别吵立场，算账

**卡1｜坑卡**
一方私下答应了长辈"我们会要二胎的"。
💥 替对方做了人生重大决定，比不要二胎本身伤关系一百倍。

**卡2｜坑卡**
"你不想要就是不爱我/不为这个家想。"
💥 立场之争一旦升级到情感审判，就没有赢家——只有两败俱伤。

**卡3｜认知卡**
"要不要二胎"其实是三道题：**钱够不够、人手谁出、 careers 谁让**。把一道立场题拆成三道算术题，才谈得下去。

**卡4｜话术卡**（留余地）
"我现在的想法是 X，但我承认想法会变——咱们先不定死，约个时间（比如半年后）再聊一次？"

**卡5｜话术卡**（算账）
"咱们一件一件算：账上每月结余、老人能不能带、谁的工作弹性大。算完再决定，谁也不用被说服。"

**卡6｜话术卡**（对被催生）
"妈，这事我们俩有规划，定了一定第一时间告诉您。"（两口子先统一口径，再各自挡各自家的长辈。）

**卡7｜演练卡**
婆婆饭桌上催生，伴侣低头不表态。你：
A. "我们还没想好。"（把分歧公开化）
B. 笑着岔开话题，回家对伴侣说："刚才那场面咱俩得先对个口径，下次你先来挡。" ✔
C. 当场表态"我们肯定生"（or 不生）。（替两人做了主）
解析：先内部统一，再对外输出——顺序反了必炸。

**卡8｜行动卡**
① 各自写下要/不要的三个真实理由 ② 列出养娃成本粗账 ③ 约定"半年后再谈"的日历提醒。

## 议题 05｜婆媳边界：谁的父母谁去说

**卡1｜坑卡**
"你妈又……"——把伴侣当成传话筒和裁判。
💥 TA 被夹在两个最爱的人中间，进退都是错。你把 TA 逼成裁判的那一刻，TA 只能判你输。

**卡2｜坑卡**
当面忍、回家炸，伴侣成了唯一出气筒。
💥 长辈没收到任何信号，伴侣平白挨了所有子弹——最差的处理方式，没有之一。

**卡3｜认知卡**
立规矩的顺序永远是：**小两口先统一 → 谁的父母谁去说**。子女对自己的父母有"豁免权"，媳妇/女婿说同样的话就是战争。

**卡4｜话术卡**（对伴侣）
"我跟你说咱妈那件事，是想和你一起想办法，不是让你选边站。咱们先统一个口径，再由你去说。"

**卡5｜话术卡**（对长辈）
"妈，这事我们俩商量过了，打算这样办。您放心，有变化第一时间跟您说。"（态度软，立场硬。）

**卡6｜话术卡**（划界前置）
"咱俩先把规矩定好：哪些事父母可以提意见，哪些咱俩说了算。定好了，各自的父母各自去沟通。"

**卡7｜演练卡**
婆婆没打招呼，说明天来小住半个月。
A. 忍了，回家对伴侣发火。
B. 立刻跟伴侣说："妈要来，咱俩先对个欢迎方案——住多久、怎么安排，然后你去跟妈确认。" ✔
C. 自己直接给婆婆打电话拒绝。（越级处理）
解析：B 走"内部统一→原生家庭成员出面"的标准流程，三方体面。

**卡8｜行动卡**
① 列出"可商量/不可商量"清单 ② 约定：一方父母越界时，另一方 24 小时内由其本人去沟通。

## 议题 06｜冷战修复：暂停可以，停战要有期限

**卡1｜坑卡**
用沉默惩罚对方，等 TA 先低头。
💥 冷战是"你不按我的来，我就撤回爱"。短期赢了姿态，长期输了安全感。

**卡2｜坑卡**
"你现在立刻给我说清楚！"
💥 情绪顶点逼人谈判，只会得到防御和更大的火。先降火，再谈事。

**卡3｜话术卡**（暂停规则）
"我们定个暗号：谁说'暂停'，另一方必须停——但暂停最长 24 小时，到点必须回来谈。"

**卡4｜话术卡**（破冰第一句）
"我不想赢这场架，我想和你是一伙的。我刚才也有不对的地方——XX。"（先给台阶，台阶不是认输。）

**卡5｜话术卡**（复盘）
"这次咱们只复盘一件事：下次遇到同样的情况，咱俩各自改哪一个动作？一人只改一个。"

**卡6｜演练卡**
冷战第三天，谁也没说话。
A. 继续等，看谁先扛不住。
B. 发出暂停暗号："我不是在赌气，我需要缓缓，今晚 8 点我们谈 15 分钟，好吗？" ✔
C. 假装什么都没发生，直接聊晚饭。（雷埋在原地）
解析：B 给冷战装了一个"24 小时到期"的出口——暂停是技术，消失才是伤害。

**卡7｜行动卡**
① 一起定暂停暗号 ② 约定"到点必谈"的具体时间机制 ③ 各自写下自己最容易上头的触发词，互相通报。

## 议题 07｜异地安排：拖到婚前才谈，是最差时机

**卡1｜坑卡**
"以后再说"——异地问题从恋爱拖到婚前，最后在装修/领证前爆炸。
💥 异地不是感情问题，是结构问题。结构问题越早摆上桌，代价越小。

**卡2｜坑卡**
默认"谁收入高/谁是男的，谁留下"。
💥 按惯性而不是按机会成本做决定，输的那一方会用很多年怨气来付账。

**卡3｜话术卡**（摆问题）
"把异地三件事写纸上：去谁的城市、各待多久、什么时候结束异地。今天不定答案，但问题必须摆全。"

**卡4｜话术卡**（机会成本）
"谁留下，不看性别不看收入——看谁的机会损失更小、谁的行业在另一座城市也能活。"

**卡5｜话术卡**（反悔机制）
"就算定了谁去谁留，也定个'反悔条款'：如果 X 个月后不适应，允许重新谈判一次，不翻旧账。"

**卡6｜演练卡**
伴侣拿到异地城市的升职 offer，希望你去 TA 的城市。
A. "为什么不是你为我回来？"（进入牺牲竞赛）
B. "恭喜！这是大事，我们用两周把两边的账算清楚：工作、收入、生活成本，然后一起决定。" ✔
C. 当场答应/拒绝。（重大决定情绪化拍板）
解析：先恭喜、再进入结构化评估——B 让"谁付出"变成"我们一起算"。

**卡7｜行动卡**
① 列出双城各自的收入/成本/职业机会对照表 ② 设定结束异地的最晚期限 ③ 约好"反悔条款"的触发条件。

## 议题 08｜见家长：情报先行，表现其次

**卡1｜坑卡**
把见家长当面试：过度表演勤快、抢话、猛刷存在感。
💥 长辈要的不是"能干的孩子"，是"让我孩子以后过得踏实的孩子"。用力过猛=心虚。

**卡2｜坑卡**
事前不做情报交换，踩了对方家里的忌讳（离婚话题、收入攀比、宗教饮食）当场社死。

**卡4｜话术卡**（敏感问题挡箭牌）
被问工资/买房/生娃："阿姨，这个我们正在规划呢，定下来第一个告诉您。"（微笑，不接具体数字。）

**卡5｜话术卡**（表现原则）

**卡6｜演练卡**

# 附录 A：受众策略与文案基调规范（女性优先）

## 一、定位决策
核心付费人群 = **25-35 岁、处于谈婚论嫁阶段的女性**。理由：婚恋内容消费女性占比 70%+；
女性是"婚前谈清楚"议题的发起者；双人邀请的实际发起方预计以女性为主。

## 二、倾斜方式（允许且要求）
| 层 | 做法 |
|---|---|
| 首页/分享文案 | 以她的视角起句："结婚前，这 8 件事你们要谈清楚" |
| 插画与视觉 | 温暖细腻、以女性角色为主体的场景插画 |
| 案例视角 | 锦囊场景主角以"她"为第一视角（话术卡保留双方处境版，已具备） |
| 专属卡 prompt | 默认以发起方（多为她）为话术输出对象："给甲方 2 句为乙方量身定制的话术"——天然偏向帮她表达 |
| 渠道投放 | 小红书为主阵地，内容选题从女性痛点出发 |
| 报告口吻 | "保护你"的安全感基调，而非"教育你" |

## 三、红线（不因受众倾斜而放松）
1. **题目与计分保持绝对中立**：任何一道题、任何评分规则不得有性别偏向。
   理由：双人测评的另一方必须愿意答题——内容一边倒，男方拒答，产品逻辑直接崩。
2. **话术卡保持双方处境版本**（彩礼卡②男方处境、卡③女方处境并存），仅案例主视角偏女性。
3. 禁止"女生必看/男人都靠不住"类性别对立文案（P7 与增补 v0.2 红线不变）。
4. 投诉风险考虑：被男方看到"偏心"内容 → 截图传播 → 审核与口碑双重风险。

> 一句话原则：**用她的语言说话，但绝不说另一方的坏话。**
